# Martin 美股选股器

把 Martin Luk 公开分享的选股条件，变成打开浏览器就能使用的美股观察工具。

扫描市场、整理候选、查看日K，把每天重复筛选和切换图表的时间，留给真正需要判断的交易机会。

**[打开网页版](https://cat4fire.github.io/martin-us-watchlist/)** · [查看每日更新状态](https://github.com/cat4fire/martin-us-watchlist/actions)

## 为什么做这个工具

研究一种交易方法，往往从一份观察名单开始。但每天手动设置筛选条件、复制股票代码、切换图表，很容易消耗大量时间。

这个项目借助 AI 编程工具 Codex 开发，将 Martin Luk 公开介绍的选股流程整理为可重复执行的筛选程序，并提供免费的网页查看入口。

它帮助你回答两个问题：**今天有哪些股票值得研究？这些股票的日线结构是什么样？**

这是独立开发的研究工具，与 Martin Luk 无官方关联。复现公开选股条件，不等于复现其全部交易决策或投资成绩。

## 你可以用它做什么

- **查看美股候选名单**：以美国交易所证券目录为基础，排除 ETF，再对能够匹配到行情的证券执行筛选；页面显示覆盖情况。
- **切换不同观察池**：查看 Potent、盘前观察 Premarket、强势股 Leader，以及 Potent 盘中快照。
- **直接看图**：点击股票代码，查看日K、成交量，以及 EMA9、EMA21、EMA50。
- **连续翻图**：使用键盘上下键切换股票；鼠标滚轮缩放，拖动图表查看历史。
- **按自己的习惯整理**：搜索股票、筛选均线分组、点击列名排序、拖动调整栏目位置、导出 CSV。
- **比较参考结构**：查看参考突破位、失效位、风险比例和辅助判断依据。
- **回看历史入选记录**：查看曾经入选的股票、最后入选日期和保留的选股快照。

访客无需安装 Python、Codex 或桌面软件，使用 Windows 或 Mac 浏览器即可访问。

## 如何使用

1. 打开网页版，先查看页面上的更新时间和完整交易日，确认当前数据对应哪一天。
2. 选择观察池。日常研究可先从 Potent 开始，再结合 Premarket 或 Leader 比较。
3. 根据需要搜索、排序或筛选，点击股票代码查看日K。
4. 使用上下键连续翻图，结合均线、成交量和价格结构缩小关注范围。
5. 查看辅助参考位及其判断依据，再自行制定交易计划。

“恢复初始排序”恢复股票的默认排列，不会重置你调整过的栏目顺序。

历史名单中的股票曾经符合条件，**不代表现在仍通过筛选**。历史选股快照与较新的日线分析应结合各自日期阅读。

## 选股条件

下面是本项目采用的公开扫描条件。不同观察池承担不同任务，并非所有条件叠加为一次筛选。

| 观察池 | 主要条件 | 用途 |
| --- | --- | --- |
| Potent | 市值大于 1 亿美元；周波动率大于 3.5%；收盘价高于 EMA21；日成交额大于 5000 万美元 | 建立日常研究名单 |
| Premarket | 市值大于 1 亿美元；10 日平均成交量大于 50 万股；日成交额大于 5000 万美元；按盘前涨幅排序 | 观察盘前活跃股票 |
| Leader | 市值大于 1 亿美元；10 日平均成交量大于 50 万股；周成交额大于 3 亿美元；按近一个月表现排序 | 寻找市场强势股 |

Potent 使用完整日数据，以减少未收盘价格变化造成的名单波动；Potent 盘中快照、Premarket 和 Leader 使用发布时获取的扫描快照。网页本身不提供实时扫描。

**EMA9 > EMA21 > EMA50 是可选的均线分组条件，并非所有观察池共同的硬性门槛。ADR > 5% 为偏好，不额外硬筛。** 周波动率与 ADR 是不同指标。

策略参考：[Martin Luk 公开视频（2024）](https://www.youtube.com/watch?v=-6lPuMFSMG0)。实现范围以本文及源码为准，不能据此认定完整复制了他的当前交易系统。

## 辅助分析如何理解

辅助分析与电脑版使用相同的核心判断模块，用于观察日线结构和比较候选，属于本项目增加的规则，**不是 Martin 本人公布的买卖信号公式**。

| 栏目 | 含义 |
| --- | --- |
| 参考突破位 | 根据所识别结构，采用最新完整日高点，或三日收紧结构的三日最高价 |
| 距突破位 % | （参考突破位 ÷ 完整日收盘价 − 1）× 100% |
| 参考失效位 | 根据所识别结构，采用最新完整日低点，或三日收紧结构的三日最低价 |
| 参考风险 % | （参考突破位 − 参考失效位）÷ 参考突破位 × 100%，未包含滑点和交易费用 |
| 辅助判断依据 | 展示结构判断的具体理由，或无法分析的原因 |

这些参考位用于辅助观察，不构成自动买入、卖出或固定止损指令。项目不连接交易账户，也不自动下单。

## 几个日期有什么区别

- **选股日期**：选股快照所依据的日期。
- **分析日线日期**：计算辅助结构时使用的最后一根完整日K日期。
- **最后入选日期**：该股票最后一次被记录通过对应观察池筛选的日期。内部按 UTC 记录，页面显示年月日；它不是准确的移出日期。

例如，一只股票上周入选，今天已经移出名单，但仍有新的日K缓存：历史选股日期可以停留在上周，分析日线日期则可以更晚。

## 每日更新与行情数据

网站通过 GitHub Actions 获取行情、生成静态数据，再部署到 GitHub Pages。计划每天 **北京时间 07:40（UTC 23:40）** 更新；GitHub 的调度可能延迟，实际是否成功以 Actions 和网页时间为准。

- 初次获取约六年历史，上市时间不足的证券以实际可用历史为准。
- 后续优先使用缓存，仅请求缺失日期和一个重叠交易日用于校验；缓存失效或复权口径变化时，可能重新获取完整历史。
- 更新范围包括所有观察池的当前入选股票，没有 120 或 500 只的下载上限。
- 当前候选必须全部具有有效日K，才发布新版本；若有股票缺少有效日K，更新停止，线上保留上一次成功发布的版本。
- 历史移出股票尽量使用保留的缓存，不保证始终拥有最新日K。
- 对少量符合严格条件的陈旧异常日K，程序会隔离并保留异常记录，在图表中说明；不会修改价格或补造K线。

证券目录及行情使用外部数据服务，包括 TradingView 扫描快照、Nasdaq 和 Yahoo Finance 历史数据。网络限制、数据异常、限流或 GitHub 缓存回收都可能影响更新。**页面展示的是已发布的快照，不是实时行情。**

## 用 AI 开发这个项目的经验

这个工具并非一次提示就完成。开发中反复遇到的问题，也形成了几个实用经验：

1. **先把规则写清楚。** “按日线选股”还不够，需要明确未收盘K线是否参与、时区如何处理，以及哪些条件是偏好而非硬筛。
2. **用具体案例定位问题。** 给出股票代码、错误日志和预期结果，比笼统地说“图表坏了”更容易找到原因。
3. **区分上传成功和部署成功。** 文件进入仓库后，还需要下载、验证和部署全部通过，网站才会更新。
4. **验证数据，而不只验证页面。** 能打开网页并不代表每只股票都有有效行情；修复后要回查曾经失败的股票。
5. **保留人工判断。** AI 负责协助实现程序，程序负责重复筛选，策略解释和交易决定仍由使用者确认。

## 自己部署或运行

普通访客直接使用网页版即可。需要维护自己的副本时，可将本目录内容放到 GitHub 仓库根目录，包括 `.github` 文件夹。

1. 在仓库 Settings → Pages 中，将 Source 设为 **GitHub Actions**。
2. 在 Actions 中打开 **Daily watchlist and GitHub Pages**，手动运行一次。
3. 等更新与部署成功后，使用部署结果中的 Pages 地址。

定时任务、数据源及托管均受相应服务限制。公开仓库长期无活动时，GitHub 可能停用定时任务，需要检查 Actions 状态。使用或再分发数据时，请遵守相应数据源条款。

本地运行需要 Python 3.12：

```bash
python -m pip install -r requirements.txt
python publish_data.py --refresh
python verify_data.py
python -m http.server 8765 --directory dist
```

然后在浏览器打开 http://localhost:8765。请通过本地服务器预览，而非直接双击 HTML 文件。

| 文件或目录 | 用途 |
| --- | --- |
| `dist/` | 网页及生成的公开数据 |
| `scanner_core/` | 选股和日线分析核心模块 |
| `publish_data.py` | 获取数据并生成发布快照 |
| `incremental_history.py` | 历史行情缓存与增量更新 |
| `verify_data.py` | 发布前数据检查 |
| `.github/workflows/daily.yml` | 每日更新和部署流程 |
| `state/` | 持久化候选记录和下载诊断 |

## 使用边界

这是选股研究与复盘工具，不是收益承诺或投资建议。筛选条件只负责缩小观察范围，无法替代风险管理、仓位控制和交易执行。历史表现不代表未来结果。
